# Git vs SVN

**1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?**

В Git ветка — это просто указатель на конкретный коммит (небольшой файл-ссылка), поэтому создание новой ветки происходит мгновенно и не требует копирования файлов. В SVN ветка физически реализована как копия директории репозитория, поэтому создание ветки — это операция копирования, которая занимает время и место, особенно на больших проектах.

**2. Можно ли в SVN сделать коммит без интернета? Почему?**

Нет. SVN — централизованная система: у разработчика на компьютере есть только рабочая копия файлов, а вся история хранится на одном центральном сервере. Коммит — это отправка изменений на сервер, поэтому без подключения к нему закоммитить нельзя. В Git у каждого разработчика есть полная копия репозитория со всей историей, поэтому коммиты делаются локально и полностью офлайн, а синхронизация с сервером (push/pull) — отдельный, самостоятельный шаг.

**3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?**

- В legacy-системах, где инфраструктура и процессы годами завязаны на SVN, и миграция на Git обходится дороже, чем поддержка текущего решения (часто встречается в госсекторе и банках).
- Когда нужен простой централизованный контроль доступа к отдельным папкам репозитория — в SVN это настраивается проще, чем в Git.
- При работе с большими бинарными файлами без Git LFS — SVN исторически лучше справляется с версионированием тяжёлых бинарников за счёт централизованной модели хранения.
